プロファイルに搭載された 4 つの機能を紹介します：プラットフォーム API 接続情報をプロファイルに保存してプロファイル切り替えと同時に環境切り替え、read-only 権限で書き込みコマンドをブロック、デフォルトマシンユーザーの固定、override deny による identity エスカレーション防止。コマンドには copy ボタン付き。

Part 1

機能説明

プロファイル・プラットフォーム設定・デフォルトマシンユーザー・override deny・.envrc コンボの概念を整理します。

プロファイルとは
ユーザー × ワークスペースの「名前付きペア」
tailor-sdk login で認証したあと、プロファイルが「どのワークスペースに対してコマンドを実行するか」を保持します。 -w <workspace-id> を毎回指定する必要がなくなり、切り替えも --profile ひとつで完結します。 

tailor-sdk profile list
→ name / user / workspaceId / permission / machineUser の表が表示されます。
活性化の優先順位
コマンド実行時のプロファイルは以下の優先順位で解決されます：
1 位（最優先） --profile <name> フラグ
2 位 TAILOR_PLATFORM_PROFILE 環境変数
3 位 カレントログイン（login 時の状態）
プラットフォーム設定
プラットフォーム API 接続情報をプロファイルに保存する
ワークスペースが非デフォルトの Tailor Platform インスタンス（カスタムドメイン）上にある場合、 profile create に --platform-url・--oauth2-client-id・--console-url を渡します。一度保存すれば、プロファイルを切り替えるだけで API URL・OAuth2 クライアント・コンソール URL がすべて切り替わります。環境変数の再 export は不要です。

初回セットアップ（Platform インスタンスごとに 1 回のみ）： 
export TAILOR_PLATFORM_URL=https://<org>.tailor.tech
export TAILOR_PLATFORM_OAUTH2_CLIENT_ID=<oauth2-client-id>
export TAILOR_PLATFORM_CONSOLE_URL=https://console.<org>.tailor.tech

tailor-sdk login
tailor-sdk profile create staging \
  -u you@example.com \
  -w <staging-workspace-id> \
  --platform-url "$TAILOR_PLATFORM_URL" \
  --oauth2-client-id "$TAILOR_PLATFORM_OAUTH2_CLIENT_ID" \
  --console-url "$TAILOR_PLATFORM_CONSOLE_URL"

unset TAILOR_PLATFORM_URL TAILOR_PLATFORM_OAUTH2_CLIENT_ID TAILOR_PLATFORM_CONSOLE_URL
以降は環境変数なしで使えます： 
tailor-sdk deploy -p staging
tailor-sdk open -p staging
tailor-sdk login -p staging    # URL を再 export せずにトークンを更新
保存した設定を消すには空文字を渡します： profile update staging --platform-url ""
マシンユーザー
デフォルトマシンユーザー — 未指定時のフォールバック
プロファイル作成時に -m <machine-user> を渡すと、コマンドにマシンユーザーが指定されていない場合にそのプロファイルのデフォルトが自動で使われます。

マシンユーザーの解決優先順位も同じ構造です：
1 位（最優先） --machine-user <name> フラグ
2 位 TAILOR_PLATFORM_MACHINE_USER_NAME 環境変数
3 位 プロファイルのデフォルト（-m で指定したもの）
--machine-user-override deny — identity の固定
profile update --machine-user-override deny を設定すると、CLI フラグ・環境変数のどちらからも 別のマシンユーザーを指定できなくなります。 指定した瞬間に PROFILE_MACHINE_USER_OVERRIDE_DENIED エラー。

「同じ値を渡す」のは OK — deny はあくまで「別の identity への切り替え」を禁止します。

適用範囲: query / workflow start / function test-run / machineuser token などアプリケーションデータ操作コマンド全般。
.envrc コンボ（direnv）
cd するだけで環境が切り替わる
各ディレクトリに .envrc を置き direnv でオートロード。dev / stg / prod を別ディレクトリ（worktree）に分ければ、 「間違ったワークスペースに deploy した」がなくなります。 
# .envrc の例（ディレクトリに配置）
export TAILOR_PLATFORM_PROFILE="show-and-tell"

# デフォルトマシンユーザーも環境変数で指定できます
export TAILOR_PLATFORM_MACHINE_USER_NAME="manager-machine-user"
初回のみ direnv allow が必要です。この show-and-tell worktree 自体が TAILOR_PLATFORM_PROFILE="show-and-tell" を .envrc で設定しています（ライブ例）。
Part 2 — Live Demo

Read-only profile + read-only machine user

ステージング環境を「見るだけ」にする 2 層ガード。CLI ガード（プロファイルの permission）と サーバーサイドガード（マシンユーザーの権限 + override deny）を重ねます。

Workspace: sdk-show-and-tell WS ID: 5d80e666-2f32-499f-b878-213229a558b8 Machine user: manager-machine-user User: akira_higuchi@tailor.tech
⚠ example/ ディレクトリから実行してください。トークン/クエリコマンドは -c tailor.config.ts で設定を明示します。
0. 作業ディレクトリへ移動
[00] show-and-tell worktree の example/ へ移動 
cd /Users/toiroakr/workspace/sdk-bare/show-and-tell/example
Layer 1 — CLI ガード（read-only プロファイル）
[01] --permission read でプロファイルを作成
--permission read を付けると、deploy・truncate・workflow start・secret set などの書き込み系コマンドが即座に失敗します。query / list / describe などの読み取りは通ります。 
tailor-sdk profile create stg-readonly -u akira_higuchi@tailor.tech -w 5d80e666-2f32-499f-b878-213229a558b8 --permission read
✓ 期待値: permission = read でプロファイルが作成される
[02] 書き込みコマンドはブロックされる 
tailor-sdk deploy -c tailor.config.ts --dry-run --profile stg-readonly
✗ 期待値: Error [PROFILE_READONLY] — "blocks platform-state mutations (apply, create/update/delete, deploy, ...). Application-data operations remain available because their permissions are governed by the machine user."
[03] 読み取りコマンドは通る 
tailor-sdk query --engine gql -q '{ users(first: 1) { edges { node { name } } } }' -m manager-machine-user -p stg-readonly -c tailor.config.ts
✓ 期待値: users が JSON で返る
Layer 2 — サーバーサイドガード（machine user ピン留め）
[04] マシンユーザーを固定する（override deny）
プロファイルが CLI の書き込みを止め、マシンユーザー自身のロール権限がサーバーを守ります。実際のステージング運用では、TailorDB / IdP の権限が read-only なマシンユーザーをここに指定します。 deny により、プロンプトインジェクションや誤ったツール呼び出しでより特権のあるマシンユーザーに切り替えようとしても即座にエラーになります。 
tailor-sdk profile update stg-readonly -m manager-machine-user --machine-user-override deny
✓ 期待値: machineUserOverride = deny に更新される
クリーンアップ
[05] デモ用プロファイルを削除 
tailor-sdk profile delete stg-readonly
✓ 期待値: Profile "stg-readonly" deleted successfully.
AI エージェント / MCP との組み合わせ
[info] なぜ AI 環境に重要か
AI エージェントや MCP サーバーはリアルな環境に対してクエリを発行するケースが増えています（RAG・分析・デバッグ）。この read-only プロファイル + read-only マシンユーザーをローカルのエージェントに向けることで：
  • ステージングデータの閲覧・検索はできるが、deploy・mutation・削除は不可
  • プロンプトインジェクションやバグったツール呼び出しが書き込みにエスカレートしない
  • --machine-user-override deny により、より特権のあるユーザーへの切り替えも不可
CLI とプラットフォームの両方で一つの read-only identity が強制される — 自分のローカル環境にスコープされた安全ガード。
Part 3 — リファレンス

プラットフォームプロファイルの設定手順

プロファイルにプラットフォーム API 接続情報を保存し、プロファイル切り替えだけで環境全体を切り替える方法。

⚑ このセクションは、ワークスペースが非デフォルトの Tailor Platform インスタンス（カスタムドメイン）上にある場合に該当します。デフォルトプラットフォームでは -u と -w のみで十分です。
初回セットアップ（Platform インスタンスごとに 1 回）
[A1] プラットフォーム URL を export してログイン
接続変数を export したうえで login します。認証情報は Platform URL にスコープして保存されます。 
export TAILOR_PLATFORM_URL=https://<org>.tailor.tech
export TAILOR_PLATFORM_OAUTH2_CLIENT_ID=<oauth2-client-id>
export TAILOR_PLATFORM_CONSOLE_URL=https://console.<org>.tailor.tech

tailor-sdk login
✓ 期待値: ブラウザが開き認証完了
[A2] プラットフォーム設定付きでプロファイルを作成
同じ env vars を --platform-url・--oauth2-client-id・--console-url として渡します。ワークスペース ID と一緒にプロファイルに保存されます。 
tailor-sdk profile create staging \
  -u you@example.com \
  -w <staging-workspace-id> \
  --platform-url "$TAILOR_PLATFORM_URL" \
  --oauth2-client-id "$TAILOR_PLATFORM_OAUTH2_CLIENT_ID" \
  --console-url "$TAILOR_PLATFORM_CONSOLE_URL"
✓ 期待値: Profile "staging" created successfully.
[A3] env vars を unset — 以降は不要 
unset TAILOR_PLATFORM_URL TAILOR_PLATFORM_OAUTH2_CLIENT_ID TAILOR_PLATFORM_CONSOLE_URL
以降の日常操作（env vars 不要）
[A4] deploy と open — プロファイルがすべて持っている 
tailor-sdk deploy -p staging
tailor-sdk open -p staging
✓ 期待値: staging ワークスペースにデプロイ。正しいコンソール URL が開く
[A5] URL を再 export せずにトークンを更新
login -p はプロファイルに保存された Platform URL と OAuth2 クライアント ID を読み取り、そのプラットフォームに対して再認証します。 
tailor-sdk login -p staging
✓ 期待値: そのプロファイルの Platform 向けにブラウザが開き、トークン更新
まとめ / Talking points
  • プラットフォーム設定（--platform-url・--oauth2-client-id・--console-url）はオプション。デフォルト Tailor Platform のワークスペースには不要。
  • ログイントークンは Platform URL ごとにスコープされる。Platform ごとに 1 回ログインすれば、あとはプロファイルを切り替えるだけ。
  • 保存した設定を消すには空文字：profile update staging --platform-url ""
  • マシンユーザー優先順位: --machine-user > TAILOR_PLATFORM_MACHINE_USER_NAME > プロファイルのデフォルト
  • --machine-user-override deny は CLI・env var の両方からの identity 切り替えを設定レベルで禁止する
  • 対象コマンド: query / workflow start / function test-run / machineuser token
  • プロファイルは開発者ローカルの設定。自分の操作と、ローカルで動かす AI エージェント / MCP を guard するものであり、org 全体への強制ではない
