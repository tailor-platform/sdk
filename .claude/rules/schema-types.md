# Schema Types

## File Structure in `src/types/`

| File type        | Example                      | Role                                                                |
| ---------------- | ---------------------------- | ------------------------------------------------------------------- |
| `*.generated.ts` | `tailordb.generated.ts`      | Auto-generated by zinfer from Zod schemas. **Do not edit manually** |
| `*.ts` (manual)  | `tailordb.ts`, `auth.ts`     | Hand-written types: derived types, utility types, type guards       |
| Standalone       | `app-config.ts`, `plugin.ts` | Hand-written types not tied to a generated file                     |

**Flow:**

```
parser/**/schema.ts (Zod schemas)
    ↓ [pnpm generate]
src/types/*.generated.ts (auto-generated types)
    ↑ [import type]
src/types/*.ts (manual: derived types, utilities)
```

## Where to Define Types

- **`src/types/`**: Internal types shared across layers — generated types, parsed data structures, problem domain models (permissions, metadata, type source info)
- **`src/configure/`**: User-facing API types — field builder types (`TailorField`), fluent method chain generics, service configuration types that SDK users directly interact with. Types here must stay close to the implementation for generic type inference to work correctly.

## zinfer Generation

**Command:** `pnpm -C packages/sdk generate`

**Config:** `packages/sdk/zinfer.config.ts`

- Source: Zod schemas in `src/parser/**/schema.ts` (exports ending with `Schema` suffix)
- Output: `src/types/[dir].generated.ts` (directory name becomes filename)
- `map` option renames types (e.g., `TailorDBTypeSchema` → `TailorDBTypeRaw`)
- `.describe("...")` on schema fields generates TSDoc comments in output types
- Each schema produces both Input and Output type variants

## Import Rules

Shared types must be imported via `@/types/`:

```typescript
// ✅ Correct
import type { TailorDBTypeRaw } from "@/types/tailordb.generated";
import type { Permissions } from "@/types/tailordb";

// ❌ Wrong: direct cross-layer import
import type { TailorDBTypeRaw } from "@/parser/service/tailordb/types";
```

## Workflow When Changing Zod Schemas

1. Edit `src/parser/**/schema.ts`
2. Run `pnpm -C packages/sdk generate` to regenerate `src/types/*.generated.ts`
3. Update `src/types/*.ts` (manual types) if new derived types are needed
4. Run `pnpm exec turbo run check` to verify build, lint, and typecheck
