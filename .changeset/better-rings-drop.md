Errors about a missing or unknown Auth service, IdP, invoker, migration machine user, or executor trigger target now point at the file to fix. `tailor deploy` and `tailor tailordb migration test` prefix the message with that file, put it in `error.context.file`, and annotate it in GitHub Actions; `tailor tailordb migration validate` prefixes the failed check's message in its report with it and puts it in that check's `error.context.file`. A service or machine user the config lacks (`AUTH_CONFIG_REQUIRED`, `MACHINE_USER_REQUIRED`, `MACHINE_USER_NOT_FOUND`, `AUTH_MACHINE_USER_NOT_FOUND`, `EXECUTOR_IDP_REQUIRED`) points at the config; an error the executor or resolver fixes (`EXECUTOR_IDP_NOT_FOUND`, `EXECUTOR_IDP_AMBIGUOUS`, `INVOKER_AUTH_REQUIRED`, `INVOKER_MACHINE_USER_NOT_FOUND`, `EVENT_SUBSCRIPTION_OWNER_NOT_FOUND`, `DEPLOY_RESOURCE_NOT_FOUND`, `DEPLOY_RESOURCE_NAMESPACE_AMBIGUOUS`) points at that executor or resolver file. `DEPLOY_RESOURCE_NOT_FOUND` and `DEPLOY_RESOURCE_NAMESPACE_AMBIGUOUS` now also name the executor, `INVOKER_AUTH_REQUIRED` suggests naming the Auth service with `invoker: { namespace, machineUserName }`, and the `AUTH_CONFIG_REQUIRED` error for an executor with an `authAccessToken` trigger names the executor and suggests defining an Auth service in the config.
