Spread `deploy`'s function/script/static website uploads across a small pool of HTTP/2 connections (default 4, tunable via `TAILOR_UPLOAD_CONNECTIONS`) instead of multiplexing them all on one. Since Node 24.2.0 (backported to the 22.x LTS line as of Node 22.23.0), nghttp2 dropped its legacy priority-tree stream scheduler in favor of RFC 9218, whose default urgency/incremental values make strict stream-ID-order processing the spec-recommended behavior for streams that don't request otherwise — and Node's http2 client currently gives a caller no way to opt a stream into incremental scheduling instead. The practical effect: uploads sharing one connection can finish 12x+ apart in wall-clock time even though aggregate throughput is unchanged, making individual uploads more likely to exceed the platform's per-upload timeout. Measured directly: spreading the same uploads across more connections narrows that spread from 12.3x (1 connection) to 3.0x (4) to 1.86x (8), independent of round-trip latency. A synthetic local benchmark against a bare Node.js HTTP/2 server also showed aggregate/per-upload throughput scaling ~linearly with connection count, but that scaling did not reproduce against the real platform at the payload sizes and latency this was tested with, so it should be treated as unconfirmed for production traffic — the scheduling fix above is the part backed by direct measurement against real uploads.
