**Breaking change**: `TailordbQueryResult`, also exposed as `tailordb.QueryResult`, has a required `fields` listing each column's name and PostgreSQL type name, which the Platform returns with every result. Code that builds a result by hand, such as a test double for `tailordb.Client` that returns `{ rows, command, rowCount }`, no longer type-checks. Add `fields: []`, or the columns the test needs, to what it returns. Code that only reads results is unaffected, and `mockTailordb` returns an empty list.

**Breaking change (beta)**: The sixth argument of `bundleMigrationScript`, exported from `@tailor-platform/sdk/cli`, is now an object that takes `temporal` and `decimal` instead of the `temporal` boolean. Replace `true` with `{ temporal: true }`. A TypeScript caller that still passes `true` stops compiling, and a JavaScript caller gets a client without Temporal values and no error.

Add a `decimal` option to `kyselyTypePlugin`. With `decimal: true`, the generated table types give decimal columns the type `Decimal` from decimal.js on read and `Decimal | string` on write, and the generated `getDB` returns `Decimal` values and accepts `Decimal` as a query parameter, sent without an exponent. Columns are found by the column types the query result reports, so an alias such as `select price as p` and an aggregate such as `sum(price)` are converted too, and float and integer columns are not. Every result column reported as numeric becomes a `Decimal`, including aggregates and arithmetic over decimal columns such as `sum(price)` and `price * 2`; aggregates over integer or float columns stay numbers. Kysely types an aggregate such as `sum()` as `string | number | bigint`. A decimal field inside an object stays a string. It works with `distPath` and with `contentMapper: true`; with `contentMapper: true`, the `getDB` imported from `@tailor-platform/sdk/plugin/kysely-type/db` returns `Decimal` values.

`createGetDB` takes a `decimal` option (the `Decimal` class), and `TailorDBInsertable`, `TailorDBSelectable`, and `TailorDBUpdateable` take a third `IsDecimal` type parameter that follows the same mapping.

A migration generated with `decimal: true` types its `db.ts` with `Decimal` columns, records `decimal` in `diff.json`, and runs its script with `Decimal` values on deploy; its generated `migrate.test.ts` passes the `Decimal` class to `createKyselyPGlite`. Only such a migration is written as format version 9, which older SDK versions refuse to read; other migrations keep format version 8. `mockTailordbWithPGlite` returns the column names and PostgreSQL type names next to the rows, and `createKyselyPGlite` accepts a `decimal` option.
