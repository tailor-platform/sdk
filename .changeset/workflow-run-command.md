Add `tailor workflow run <file>`, which runs a workflow job as a temporary workflow without deploying it. The job (`--job`, optional when the file defines only one) becomes the first job of the temporary workflow, and every job it starts with `.start()` is registered under a name of its own, so the deployed jobs of the same name are never touched. A job that calls `.start()` is suspended until the started job finishes, so work that does not fit in one job (the Platform ends a job after 5 minutes) can be split across jobs. A file that defines no workflow job is refused. The command waits for the run, prints the logs of every job and the result of the first job, and removes the temporary resources. `tailor workflow cleanup` removes the resources of runs whose wait was cut short (`--timeout`), and warns about resources named `tmp-run-…` that carry no label; `--include-unlabeled` removes those too. `tailor deploy` also removes the resources of finished runs at its end, and never fails because of it. `tailor workflow script <file>` scaffolds a workflow definition (two jobs and a `createWorkflow`) to run with `workflow run`.
