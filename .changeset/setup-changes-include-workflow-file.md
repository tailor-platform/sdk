The `tailor-changes` job of the workflows generated by `tailor setup ci branch` and `tailor setup ci preview` now also counts a change to the generated workflow file itself as relevant. A pull request or push that only edits the workflow, for example to add a job of your own, now runs the plan, deploy, and preview jobs instead of skipping them. To skip them for such a change, exclude the file with `--paths '!.github/workflows/<file>.yml'`. Run `tailor setup update` to regenerate existing workflows. Workflows for an app at the repository root and `tailor setup ci tag` workflows have no change detection and are unchanged.
