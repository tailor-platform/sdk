## Agent Instruction Sources

- `AGENTS.md` is the shared repository instruction entrypoint for Codex, Claude, and other coding agents.

- Run `pnpm agent:rules:update` after editing `.agents/rules.json` or `.agents/rules/*.md`. The command regenerates the rule index below and `.claude/rules/*.md`.

## Commands

### Development

- `pnpm build` - Build all packages
- `pnpm test` - Run all tests
- `pnpm check` - Run build, generate, format, lint, typecheck, knip, publint, JSDoc, and agent-rule drift checks
- `pnpm generate` - Run code generation
- `pnpm deploy` - Deploy to the Tailor Platform
- `pnpm actions:lock:update` - Regenerate `.github/workflows/actions.lock` after changing `uses:` in `.github/workflows/` or `.github/actions/`. Plain `gh actions-lock`, which the lockfile header suggests, rewrites the SHA pins that ghalint and zizmor require to tags
- `pnpm actions:lock:check` - Verify `.github/workflows/actions.lock` is up to date

### Package-specific (in packages/sdk)

- `pnpm test` / `pnpm test path/to/test.ts` / `pnpm test -t "pattern"` - Run tests with Vitest
- `pnpm build` - Build SDK
- `pnpm docs:check` / `pnpm docs:update` - Check/update CLI documentation

### Agent Instructions

- `pnpm agent:rules:update` - Regenerate `AGENTS.md`'s path-scoped rule index and `.claude/rules/*.md`
- `pnpm agent:rules:check` - Verify generated agent rule files are up to date
- `pnpm codemod:docs:update` - Regenerate `packages/sdk/docs/migration/v<major>.md` from the codemod registry
- `pnpm codemod:docs:check` - Verify migration docs are up to date
- `pnpm check:deprecations` - Verify every `@deprecated` in `packages/sdk/src` states its `since` version and codemod (see [Deprecating a Public API](.agents/rules/deprecation.md))

### CLI

See [packages/sdk/docs/cli-reference.md](packages/sdk/docs/cli-reference.md) for the full CLI reference.

Under an agent, the `tailor` CLI (not CLI plugins) defaults to JSON output; prefix `POLITTY_NO_AGENT=1` to check human output.

### CLI Documentation

[politty](https://github.com/toiroakr/politty) generates `packages/sdk/docs/cli-reference.md` and `packages/sdk/docs/cli/<name>.md` from command definitions and the `*.template.md` beside each file, and `docs:update` overwrites the output in full. Edit the template or the command's `description` / `notes` instead.

`docs:check` catches a command listed in `templateFiles` (`packages/sdk/src/cli/docs.test.ts`) that appears in no template. It does not catch missing placeholders for top-level commands absent from `templateFiles` or for subcommands of a parent split into section placeholders; those commands are silently left out:

- **New top-level command**: add it to a `templateFiles` entry and put `{{politty:command:<name>}}` in that entry's template.
- **New doc file**: add a `templateFiles` entry and a `docs/cli/<name>.template.md`, copying an existing template's front matter, which feeds the `cli-reference.md` index.
- **New subcommand**: `{{politty:command:<parent>}}` includes every nested subcommand. A parent split into section placeholders (`{{politty:command:tailordb:heading}}`, ...) needs a `{{politty:command:<parent> <sub>}}` for each new child.

## Code Patterns

Refer to `example/` for working implementations of all patterns (config, models, resolvers, executors, workflows).

Key files:

- `example/tailor.config.ts` - Configuration with defineConfig, defineAuth, defineIdp, defineStaticWebSite, defineAIGateway, definePlugins
- `example/tailordb/*.ts` - Model definitions with `db.table()`
- `example/resolvers/*.ts` - Resolver implementations with `createResolver`
- `example/executors/*.ts` - Executor implementations with `createExecutor`
- `example/workflows/*.ts` - Workflow implementations with `createWorkflow` / `createWorkflowJob`

Before writing code that uses the SDK, read its rules in the matching user doc under `packages/sdk/docs/` (`services/<service>.md`, `configuration.md`, `testing.md`).
